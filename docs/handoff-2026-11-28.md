## What the cloud has, and what it lacks

- **Kaggle:** the owner adds a Kaggle API token as an environment secret, either `KAGGLE_API_TOKEN` or
  `KAGGLE_USERNAME` with `KAGGLE_KEY`. `scripts/cloud-setup.sh` runs from the SessionStart hook, installs the CLI and
  checks it. If it says the API call failed, either the token is wrong or the network policy blocks `www.kaggle.com`
  or `storage.googleapis.com`. Never print, read or commit the token.
- **No GPU and no local models.** Every model call goes through a Kaggle job (`trials/kaggle/job.py`; see its
  README). The notebook clones the public repo at a pushed commit, so commit and push before every job.
- **This repository only,** unless the owner adds the others to the environment: Substrate, Morphogen, the kernel
  and `openreplicant.github.io`. The manager agent's canonical harness is in Substrate
  (`scripts/trials/manager/`, PR #34). MetaSoar has a copy for Kaggle in `trials/manager-eval/pm1a/`, with its
  source commit in `SOURCE`.
- **Not here:** files that were never committed. They include E-19's dev results and the Kaggle `runs/` folders
  (gitignored). Download a job's output again with `kaggle kernels output mossmanpete/metasoar-NAME -p DIR` if needed.

  with a Haiku-class model and move up only on evidence.

  30 GPU hours a week, at most 12 hours a session, and about 5.5 minutes of setup per job. Compare Kaggle results
  only with Kaggle baselines.

  Sonnet for ordinary work, and Opus only for hard design. On 2026-11-27 the usage limit was hit twice with
  several Opus agents running.
- **Draft PRs, and never merge** unless told to.
- **Only quoted lines are the owner's.** Doc text written by agent sessions is not their specification; check
  `git log -S` before attributing anything to them. Explain Soar jargon in plain words.
- **Git gotchas:**
  - `gh pr edit` fails on these repos; use `gh api -X PATCH repos/OpenReplicant/REPO/pulls/N -F body=@file`.
  - Deleting a stacked PR's base branch closes the PR, so retarget it first.
  - `delete_branch_on_merge` is off.
